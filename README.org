*Your build is Lisp.  Run it like Lisp.*

~maak.el~ is the Emacs front end to [[https://github.com/jjba23/maak][maak]], and both
are about one freedom: the freedom to write your build in a language you can
read, change and run without asking a tool for permission.

There is no file format to learn and no plugin API to register against.  A Maak
file is a Guile module; a task is a lambda.  ~(define (deploy target) ...)~ is
already a task, with its argument list, its optional and keyword arguments, its
dotted rest argument and its docstring — nothing to declare twice.

#+begin_quote
Most build tools invent their own limited domain-specific language.  Maak
embraces the powerful *λ Lisp* and the amazing Guile Scheme programming language.

/This also means your code is flexible, robust and reliable (+declarative) for at
least the next 50 years./
#+end_quote

Because a task is a lambda and the file is a module, everything a Lisp gives you
is already there: a task can call another task as a function, a helper is a
~define~ away, a build step can be redefined in the REPL, and the argument list
the completion menu shows is the one Guile will enforce.  ~maak.el~ reads that
file the way maak does, so ~M-x maak-run-task~ offers the tasks a run could
name, prompts for the arguments they take, and runs them in Emacs' own ~compile~
buffer — the editor, the build and the language are one Lisp, one keystroke
apart.

* What you get

- *Automatic project discovery*: finds your root ~maak.scm~ up the directory
  tree, from anywhere inside the project.
- *Smart visibility*: respects the ~#:export~ list, so only the tasks a run could
  name appear — or all of them, in a file that does not curate its own surface.
- *Polished completion*: aligned columns in your completion framework of choice
  (Vertico, Ivy, Helm or plain ~completing-read~), showing each task's arguments
  and docstring under faces your theme already sets.
- *Interactive argument gathering*: prompts for what a task needs, in the
  minibuffer, understanding Guile's whole lambda list — required, ~#:optional~,
  ~#:key~, ~#:rest~ and dotted rest arguments.
- *Native compilation buffers*: tasks run asynchronously through Emacs' own
  ~compile~ system, with shell escaping kept watertight and ~next-error~ working
  on whatever the task prints.

* Getting started in one screen

Install maak, put ~maak.el~ on your ~load-path~, bind the command:

#+begin_src emacs-lisp
(use-package maak
  :ensure (:host github :repo "jjba23/maak.el" :branch "trunk")
  :bind ("C-c m r" . maak-run-task))
#+end_src

Then, from inside any project that has a ~maak.scm~:

#+begin_src text
M-x maak-run-task
#+end_src

The menu lists the project's tasks, the minibuffer asks for what the task you
picked needs, and the task runs in a ~*compilation*~ buffer.
