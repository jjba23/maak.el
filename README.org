~maak.el~ brings seamless integration for [[https://codeberg.org/jjba23/maak][Maak: The infinitely extensible command runner, control plane and project automator à la Make (Guile Scheme - Lisp)]] into your Emacs workflow. Maak replaces archaic Makefiles with the elegance and power of GNU Guile Scheme. With ~maak.el~, you can discover, inspect, and execute your Maak tasks directly from the comfort of Emacs, complete with rich minibuffer completions.

#+begin_quote
Most build tools invent their own limited domain-specific language.  Maak embraces the powerful *λ Lisp* and the amazing Guile Scheme programming language.

/This also means your code is flexible, robust and reliable (+declarative) for at least the next 50 years./
#+end_quote

- Automatic Project Discovery: Automatically locates your root ~maak.scm~ file using dominating-file heuristics.
- Smart Visibility Parsing: Respects your Maak configuration's ~#:export~ lists—only showing public tasks (or all, if no exports).
- Polished Completion UI: Implements aligned columns in your preferred completion framework (Vertico, Ivy, Helm, or native ~completing-read~) showcasing task signatures and docstrings.
- Interactive Argument Gathering: If a task expects parameters, ~maak.el~ will sequentially prompt you for them in the minibuffer before executing, understanding Guile's full lambda list (required, ~#:optional~, ~#:key~, ~#:rest~ and dotted rest arguments).
- Native Compilation Buffers: Executes tasks asynchronously via Emacs's native ~compile~ system, keeping shell-escaping watertight and allowing you to jump straight to errors.

[[https://jointhefreeworld.org/static-assets/maak/maak-in-emacs.png]]

Using standard Emacs properties, your tasks are dynamically formatted in completion list. It will render beautifully aligned columns matching your theme's default font lock faces.

Thanks to Lisp being universal, and Scheme and Emacs Lisp being mutually parseable,  ~maak.el~ parses ~maak.scm~ locally and cleanly, while being aware of S-exps, comments, etc.

- It spins up a temporary buffer inside standard Emacs Lisp mode to parse Scheme forms safely.
- It locates the module's ~#:export~ form (handling comments and strings seamlessly) to build a whitelist.
- It maps defined procedures matching public exports (or all, if no exports), extracting Scheme docstrings and formal parameter lists.

* Installing

This package is not (yet) available in popular Emacs repositories such as MELPA or ELPA.
An example installation with Elpaca:
#+begin_src emacs-lisp
  (use-package maak.el
    :ensure (:host codeberg :repo "jjba23/maak.el" :branch "trunk")
    :demand t
    :bind ("C-c m r" . maak-run-task))
  #+end_src

It is also packaged with Nix. This repository carries the expression itself, ~default.nix~ next to ~maak.el~, so ~nix-build~ in this checkout builds the package; and it is part of [[https://codeberg.org/jjba23/nix-jointhefreeworld][nix-jointhefreeworld]], the set of Nix packages for everything Jointhefreeworld. The set's ~emacsOverlay~ adds it to ~emacsPackages~, byte-compiled and with its autoloads, so an Emacs that Nix builds gets it the way it gets any other package:
#+begin_src nix
  let
    emacsPackages = pkgs.emacsPackages.overrideScope nix-jointhefreeworld.emacsOverlay;
  in
    emacsPackages.withPackages (epkgs: [ epkgs.maak ])
  #+end_src

* Usage

 Running Tasks

Invoke the primary command:
#+begin_key
M-x maak-run-task
#+end_key

- Emacs will search upwards from your current buffer to find a ~maak.scm~.
- A completion menu will pop up listing all exported tasks from your Scheme configuration.
- If the task you select defines parameters (e.g., ~(define (deploy server env) ...)~), the minibuffer will prompt you sequentially.
- Optional arguments can be left out by answering with an empty line; they are then not passed at all, so the task's own default applies.
- A standard ~*compilation*~ buffer will spawn executing your task via ~maak  <args...>~.

Using standard Emacs properties, your tasks are dynamically formatted in completion list. It will render beautifully aligned columns matching your theme's default font lock faces.

* Task arguments

~maak.el~ reads the argument list of a task the way Guile and maak do, so the prompts and the command line agree with what the task will receive.

| Form in the Maak file                                  | What ~maak.el~ does                                                               |
|--------------------------------------------------------+-----------------------------------------------------------------------------------|
| ~(define (deploy target) ...)~                         | Prompts for ~target~. A blank answer is an error, before anything runs.           |
| ~(define* (deploy target #:optional env) ...)~         | Prompts for ~env~ too; a blank answer leaves it out of the command.               |
| ~(define* (deploy target #:optional (env "dev")) ...)~ | Shows the default; a blank answer lets the task use it.                           |
| ~(define* (deploy #:key (env "dev")) ...)~             | Shows ~#:env=dev~ in completion; never prompts, because maak passes only strings. |
| ~(define (echo . words) ...)~ or ~#:rest words~        | Prompts once for space separated words; a blank answer passes none.               |

An optional argument answered with ~RET~ is *omitted*, never passed as the empty string ~""~ -- that is what makes the default on the task's side work. Leaving out an optional argument also leaves out the arguments after it, because maak binds positional words in order: there is no way to give the third optional argument a value while the second one is empty.

Keyword arguments are displayed with their defaults but are not prompted for. A maak command line passes positional strings, and a string is not a keyword, so a keyword argument always arrives as its default; ~maak kw hello~ is an error, not a way to set a keyword. A keyword argument written without a default cannot be supplied at all, so ~maak.el~ says so before running rather than letting Guile fail with ~Missing keyword~.

#+begin_src scheme
(define* (deploy target #:optional (env "staging"))
  "Deploy TARGET to ENV."
  ...)
#+end_src

Choosing ~deploy~ and answering ~prod~ then ~RET~ runs:

#+begin_src shell
maak deploy prod
#+end_src

so the task sees ~env = "staging"~, rather than the empty string. An argument that begins with a dash is set apart with ~--~, as in ~maak quick-math -- -23 42~, and every word is shell quoted separately, so spaces and quotes in an argument survive.

* Customization

You can customize ~maak.el~ behavior and looks with Emacs Lisp config (or via ~M-x customize-group RET maak RET~ ). Some worthy mentions:

| Variable / Face                | Default Value                                    | Description                                                                                 |
|--------------------------------+--------------------------------------------------+---------------------------------------------------------------------------------------------|
| ~maak-annotation-padding~      | ~4~                                              | Number of spaces to maintain between the arguments and the docstring in completion columns. |
| ~maak-executable~              | ~"maak"~                                         | Name of, or path to, the maak executable that tasks run.                                    |
| ~maak-task-arguments-face~     | Inherits ~font-lock-variable-name-face~ (italic) | Face used to render the task arguments list in completion.                                  |
| ~maak-task-documentation-face~ | Inherits ~font-lock-doc-face~                    | Face used to render the task docstring in completion.                                       |

* Development

The project's own ~maak.scm~ defines the checks:

#+begin_src shell
maak test               # the ERT suite
maak test optional      # only the tests whose names match "optional"
maak byte-compile       # byte-compile maak.el with warnings as errors
maak ci                 # both
#+end_src

Or run the suite directly:

#+begin_src shell
emacs -Q --batch -L . -l test/maak-test.el -f ert-run-tests-batch-and-exit
#+end_src

The fixtures under ~test/fixtures~ cover every argument form. Two tests check the parser against the reference implementation: one asks Guile for the arity of each fixture task, and one asks ~maak --list~ for the task list, so a change in the grammar shows up as a failing test rather than as a stale assumption.

From Lisp, ~maak-get-tasks~ returns one ~(TASK-NAME DOCSTRING ARGUMENTS)~ entry per task, and each argument is a plist with ~:name~, ~:kind~ (~required~, ~optional~, ~key~ or ~rest~) and, when it has one, ~:default~ and ~:default-p~. A keyword argument also carries ~:keyword~.
