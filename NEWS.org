All notable changes to this project are documented in this file.  Changes are
listed per release, and within each release under additions, changes, fixes and
removals.

This project adheres loosely to [[https://semver.org/spec/v2.0.0.html][Semantic
Versioning]].

* 0.10.3 (2026-11-10)

*** Changed

- The funding file now carries a custom funding URL that points at
  [[https://buymeacoffee.com/jjbigorra][Buy Me a Coffee]], so the repository
  shows a Sponsor button.

* 0.10.0 (2026-11-09)

*** Added

- ~M-x maak-describe-task~, the inspect half of what this package claims to do.
  It shows a task's whole docstring, the command line it would run as, and one
  line per argument with its kind and default — including the keyword argument
  maak cannot pass at all.  The completion list has room for the first line of a
  docstring beside the signature; this is where the rest goes.
- ~M-x maak-goto-task~ opens the Maak file at the definition of the task you
  pick, with the same completion list the run uses, and pushes where you were
  onto the xref marker stack so ~xref-go-back~ returns.  A task you cannot
  remember the shape of is now a task you can read.
- A task entry carries its definition position, so ~maak-get-tasks~ returns
  ~(TASK-NAME DOCSTRING ARGUMENTS POSITION)~.  The first three elements are what
  they always were.

*** Fixed

- A ~maak~ that is not installed is refused before the run, with an error naming
  ~maak-executable~.  It used to reach ~compile~ and come back as a compilation
  buffer whose first line said ~Searching for program~, which reads like a build
  failure rather than a missing tool.

*** Changed

- ~maak-read-task-entry~ is the task prompt on its own, so a command that wants
  to act on a task rather than run it does not have to write the completion list
  again.  ~maak-read-task~ is that plus the argument prompts.

*** Version

- Bumped the version to 0.10.0: new commands, and no change to how a task runs.

* 0.9.4 (2026-11-09)

*** Changed

- Relicensed to the *MIT license*, code and documentation alike, replacing
  GPL-3.0-or-later and FDL-1.3-or-later.  ~COPYING~ is gone; the full text is in
  ~LICENSE~, and every source file carries an
  ~SPDX-License-Identifier: MIT~ line.  Releases up to and including 0.9.3 keep
  the terms they shipped with.
- The project lives at [[https://github.com/jjba23/maak.el]].  The ~URL~ header,
  the Nix expression, the container label, the Debian, openSUSE and Arch recipes,
  and every link in the guide all point there instead of Codeberg, which is
  archived.  [[https://github.com/jjba23/maak][maak itself]] moved with it.
- The README is a front page again: it leads with what the project is
  for — a build written in Lisp, a task that is a lambda, no DSL — and the rest
  moved into a guide under ~docs/~, one page per topic, starting at
  ~docs/index.org~.  Nothing was dropped in the move; the argument-form table,
  the customization reference, the installation routes and the development notes
  each have a page of their own, with the detail they had grown.

*** Added

- ~NEWS.org~, this file, so a release has release notes rather than only a git
  log.
- GitHub Actions run the quality gate on every push and pull request: the ERT
  suite on Emacs 28.2, 29.4 and 30.1, and a lint job on the newest that
  byte-compiles with warnings turned into errors.
- A release workflow runs the suite from a ~vX.Y.Z~ tag and attaches that tag's
  archive to the GitHub release.

*** Fixed

- ~maak-test-project-maak-file-is-wired~ knew the project's task list from before
  the ~agents~ task existed, so the suite had one failing test on ~trunk~.  The
  expected list names ~agents~ now, in the place the file defines it.

*** Version

- Bumped the version to 0.9.4.
